## 4. Loop / Graph 流程說明

本次 Workflow 設計如下：

**蒐集資料 → 資料檢查 → Ingest 至 Wiki → 建立搜尋索引 → 查詢 Wiki → 檢查內容 → 整理中文 Wiki → 產生 HTML 簡報 → 功能測試**

主要包含三種檢查與修正流程：

**資料取得檢查：** 當來源無法下載或取得內容不足時，更換資料來源並重新匯入。

**Wiki 檢索 Loop：** 當搜尋結果不符合相似度、來源或關鍵概念等條件時，改用其他問題重新搜尋，最多嘗試三次。

**內容與簡報檢查：** 確認檢索結果與主題相關、引用來源正確，並在簡報完成後測試各項功能。若發現問題，回到對應步驟修正。

這樣設計是為了避免直接使用不符合主題的資料，提升知識庫與教學內容的品質。

## 5. 一次實際執行結果與檢查紀錄

本次實作過程中，曾遇到以下問題：

**後續測試結果：**

- 5 個中文 Wiki 測試問題，全部找到預期主題。

## 6. 反思：哪個節點最常出錯？如何調整檢查流程？

這次實作中，最主要的問題出現在 Wiki 檢索與內容相關性檢查階段。

原本我認為只要搜尋結果的相似度達到標準，就代表找到正確的資料。但實際查看後才發現，有些內容雖然包含相關關鍵字，卻不是我要的教學內容。

因此，我將檢查提前到 Wiki 檢索階段，除了相似度之外，也加入來源限制、關鍵概念檢查及人工確認。

修改後，原本有問題的「LLM 模型訓練」已能找到與主題相符的資料。

透過這次作業，我了解到建立知識庫不能只看程式是否成功執行，也需要確認實際內容是否正確。利用 Loop / Graph 設計檢查與修正流程，可以更早發現問題，避免錯誤資料進入最後的 HTML 簡報。
